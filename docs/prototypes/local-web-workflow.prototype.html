Migmate local web workflow

The question this answers: what minimum local web workflow gives a human operator meaningful leverage over setup, preview, approval, execution, status, verification and reports for both job types — without duplicating the CLI? Three structurally different answers, same fixture data. Flip with the bar at the bottom (or ←/→).

Settled and binding here: the web server process is the writer — a run it starts survives the tab closing and dies with the server; refusals (lock conflict, stale-lease recovery) are rendered, never hidden; progress is counts, never an invented percentage; the archive package is read outside this UI. Undecided and handed to this ticket: how the local web server itself is bound and authenticated — each variant takes a different position, visible in its header.
